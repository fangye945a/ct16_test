# 真实设备前端对齐设计

## 目标

将 `/projects/ct16_test` 的前端页面、布局、路由和交互实现对齐到真实设备工程 `zaiohDeviceWorkSpace/frontend`，同时保留当前工程的批量运维管理模块。页面调用沿用真实设备工程的 API 组织方式，但默认由本地 mock 数据适配器返回数据，不依赖真实设备后端。

## 范围

### 纳入迁移

- 真实设备工程的 `src/api` 类型和 API 模块组织。
- 真实设备工程的深色工业控制台主题、品牌 Logo、Header、Sidebar、Layout 和认证流程。
- 真实设备工程的系统概览、拓扑、日志、OTA、Node-RED、智能体、网络设置、设备模型、北向平台和系统设置页面实现。
- 真实设备工程的页面模块入口及其页面专属组件。
- 真实设备工程的 API DTO、请求边界和前端错误处理方式。

### 保留与合并

- 当前工程的批量运维页面、批量导入弹窗、批量运维服务和相关数据模型。
- 批量运维入口使用真实设备工程的深色主题和 Sidebar 结构，路由保留为 `/batch-operations`。
- 批量运维数据继续使用当前原型的本地模拟实现，暂不接入设备 API。

### 不纳入

- 不迁移真实设备工程的 Go 后端、GN 构建脚本、Node-RED 服务和设备运行时。
- 不在本次改造中接入真实设备网络、真实 OTA 写入、真实日志 SSE 或真实硬件控制。
- 不修改 `src/index.tsx` 和 `src/components/ui/*` 的既有约束边界；如真实工程业务代码依赖组件差异，只调整业务调用侧。

## 数据适配设计

保留真实设备工程的 API 文件路径和函数命名，新增或调整 mock 实现，使 API 函数返回与真实 DTO 一致的模拟数据。页面只依赖 API 模块，不直接读取页面级 mock 数据。

- 查询接口从当前工程或真实设备工程已有数据文件生成 DTO。
- 写入接口在内存或 `localStorage` 中保存原型状态，并返回真实接口对应的成功 DTO。
- SSE 日志接口提供定时生成的模拟事件流，页面生命周期结束时关闭连接。
- Node-RED 与智能体相关接口保持原型行为，所有变更仅作用于当前浏览器或模拟工作区。
- 通过单一开关或环境变量保留将来切换真实后端的边界，但默认模式必须是 mock。

## 页面与路由

以真实设备工程路由为基线：

`/`、`/topology`、`/logs`、`/ota`、`/nodered`、`/agent`、`/device-models`、`/settings`、`/network`、`/northbound-platforms`。

新增并保留：

`/batch-operations`。

文件管理页面不再作为一级导航，除非真实设备工程路由中存在对应入口；日志页面统一使用真实设备工程的 `/logs` 结构承载文件日志、异常日志和实时日志。

## 视觉与交互

- 采用真实设备工程的深色工业主题、字号、间距、状态色和组件组合。
- 产品名称、Sidebar 文案和 Header 信息以真实设备工程为准。
- 批量运维页面只迁移外层视觉与公共布局，不改变其批量导入、任务执行、备份恢复和策略管理行为。
- 认证页面改为真实设备工程的会话模型，但 mock 模式下使用固定的本地模拟会话，不向真实后端发请求。

## 验证标准

- `npm run typecheck` 通过。
- `npm run lint:eslint` 通过。
- `npm run build` 生成可部署产物，且输出目录配置与构建脚本一致。
- 启动开发服务后可访问所有一级路由，首次访问进入 mock 登录流程。
- 每个 API 页面在后端不可用时仍能展示模拟数据和明确状态。
- 批量运维模块的导入、任务列表、任务重试、备份导出和恢复流程不回归。
- Node-RED iframe、日志模拟流和文件导出等浏览器交互正常。
